# NEXTBYTE Room Upload Fix

## Fixed in this build

- Fixed the false `Shared room not found` upload error. Room file uploads and shared-note attachments now verify the signed-in user's membership directly against Supabase and load the room record by its stable room ID instead of relying only on an in-memory `S.rooms` entry.
- Added clearer failure messages for missing membership, room read access, upload errors, and metadata insert errors.
- Successful room file and shared-note uploads append their newly inserted metadata row to the active room state immediately.
- Storage objects are removed if the associated room-message insert fails, avoiding orphaned uploads.
- File selection now shows a selected-file status; the user explicitly taps the upload/share button to submit. This avoids hidden auto-upload attempts when selecting a file.
- Preserved the supplied global NEXTBYTE background image.
- Bumped the service-worker cache version and precached `nexbyte-background.png` so clients receive the updated HTML and background.
- Set PWA orientation to `any`, while keeping portrait and landscape use available.

## Database inspection

The connected NEXTBYTE Supabase project was inspected read-only. The `study-room-files`, `user-study-files`, and `user-music` buckets exist and are private. Authenticated upload policies exist for all three buckets, including membership-based room-file upload policies. The screenshot's `Shared room not found` message is generated by the app's local-state check before Storage upload, so this specific fix is in the frontend. No new SQL migration is required for this identified error.

## Not claimed as live-tested

The code was statically checked. A real browser upload from the user's signed-in session, an upload from a second room member, and a two-device verification still require testing after deployment.
